## 項目は 2 種類に分かれます

| 区分 | 意味 | I/F 仕様に書くか |
|---|---|:---:|
| 🔵 **中核** | 画面側が**意味を理解して使う**。ガントの帯やネットワーク図を描くのに必要 | **書く** |
| ⚪ **素通し** | 表示・編集はできるが、**ツールは意味を解釈しない**。読んだまま保存し直す | **書かない** |

### どちらにするかの判断

**「この項目がないと、絵が描けなくなるか？」**で決めます。

- 期間 → 帯の長さが決まらない → **中核**
- 部署 → 表に出すだけ。絵は描ける → **素通し**

**迷ったら素通しにしてください。** 中核にすると仕様が増え、
サーバ側との合わせ込みの対象も増えます。
素通しなら、何個増えても I/F 仕様は増えません。

### 判断が変わった実例 — 担当

リソース（`assignees`）は、はじめ素通しにしていました。表に出すだけで絵は描けたからです。

その後、**リソース別に行を並べる**機能を作りました
（[`../ui/15-multi-project.md`](../ui/15-multi-project.md)）。
ここでツールは「この作業は誰のものか」を理解しないと**行を作れなく**なりました。
そこで**中核へ移しました**。

**判断基準が変わったのではなく、画面が変わったので答えが変わった**という例です。
迷ったら素通しにしておき、必要になってから中核へ移す、で構いません。

## 属性の意味

| 属性 | 必須 | 意味 |
|---|:---:|---|
| `key` | ✔ | データ上の名前。XML の要素名との対応は [`20-data-model.md`](20-data-model.md) |
| `label` | ✔ | 画面に出す名前 |
| `grp` | ✔ | `core`（中核）か `pass`（素通し） |
| `section` | ✔ | 編集画面での区分け。下の 5 つから選ぶ |
| `type` | ✔ | 入力の種類。下表を参照 |
| `options` | — | `select` のときの選択肢 |
| `unit` | — | 数値に付ける単位（`d` `%` など） |
| `w` | — | 表の列幅（px）。省略すると既定値 |
| `readonly` | — | `true` にすると編集させない |
| `help` | — | 編集画面に出す補足。編集不可の理由もここへ |

### `type` の種類

| 値 | 見え方 |
|---|---|
| `text` | 1 行の文字入力 |
| `multiline` | 複数行の文字入力。編集画面では横幅いっぱい |
| `number` | 数値入力。`unit` があれば単位を添える |
| `date` | 日付入力 |
| `select` | 選択肢から選ぶ。`options` が必要 |
| `link` | タスクどうしのつながり。専用の一覧から選ぶ（`preds` のみ） |
| `parent` | 親タスク。**検索付きの一覧から選ぶ。先頭に「最上位（親なし）」が入る** |
| `people` | **複数のリソース**。読点・カンマ・空白のどれで区切ってもよい（`assignees` のみ） |

### `section` の種類

編集画面はこの順に区分けされます。

**基本 / 日程 / 体制 / 管理 / 元データ**

ここにない区分けを書くと、末尾にまとめられます。

## 項目の一覧 🟢

> サーバ側の `GET /portfolio` の `tasks[]`（[`20-data-model.md`](20-data-model.md)）に対応します。
> `preds` `succs` `parent` `project` は JSON の `deps[]` `parentId` `projectId` から画面側が作る項目です。

| key | 表示名 | 区分 | 区分け | 型 | 選択肢 | 編集 | 補足 |
|---|---|:---:|---|---|---|:---:|---|
| `name` | タスク名 | 🔵 中核 | 基本 | text | — | 可 | 図にも表にも出る名前 |
| `kind` | 種別 | 🔵 中核 | 基本 | select | タスク / マイルストン / バッファ | 可 | サーバ側の判定は暫定（TaskType と期間ゼロから推定） |
| `progress` | 進捗 | 🔵 中核 | 基本 | number (%) | — | 可 | 暫定値。BM3 の正式な進捗率ではない |
| `parent` | 親タスク | 🔵 中核 | 基本 | parent | — | 可 | `parentId` を名前で表示。「最上位」を選ぶと親から出ます |
| `project` | プロジェクト | 🔵 中核 | 基本 | select | プロジェクトの一覧 | 可 | `projectId` を名前で表示。親を変えると親のプロジェクトに揃います |
| `duration` | 期間 | 🔵 中核 | 日程 | number (d) | — | 可 | **営業日**。土日を飛ばして完了日が決まります（祝日は未対応 `Q-041`） |
| `start` | 着手日 | 🔵 中核 | 日程 | date | — | 可 |  |
| `finish` | 完了日 | 🔵 中核 | 日程 | date | — | 可 | 着手日と期間から決まります |
| `preds` | 先行タスク | 🔵 中核 | 日程 | link | — | 可 | `deps[]` から。図の矢印と同じ |
| `succs` | 後続タスク | 🔵 中核 | 日程 | link | — | 不可 | 先行タスクの裏返し |
| `consumed` | バッファ消費 | 🔵 中核 | 日程 | number | — | 可 | バッファのみ。単位は日 |
| `protects` | 保護対象 | 🔵 中核 | 日程 | text | — | 不可 | バッファのみ。現時点は DependencyId |
| `assignees` | リソース | 🔵 中核 | 体制 | people | — | 可 | **BM3 の Skill 名（資源の種類）。** 複数可。リソース別の並べ方はこの項目を見ています |
| `wbsCode` | WBS 番号 | ⚪ 素通し | 管理 | text | — | 可 | BM3 の Task Code |
| `priority` | 優先度 | ⚪ 素通し | 管理 | select | 高 / 中 | 可 | 暫定表示（クリティカルなら 高） |
| `phase` | 工程区分 | ⚪ 素通し | 管理 | text | — | 可 | 現時点は常に空 |
| `note` | 備考 | ⚪ 素通し | 管理 | multiline | — | 可 | BM3 の Memo、またはバッファの情報 |
| `createdAt` | 起票日 | ⚪ 素通し | 元データ | date | — | 不可 | プロジェクトの AsOfDate 由来 |
| `updatedAt` | 更新日 | ⚪ 素通し | 元データ | date | — | 不可 | プロジェクトの AsOfDate 由来 |
| `sourceProjectId` | 元 ProjectId | ⚪ 素通し | 元データ | text | — | 不可 | BM3 上の識別子 |
| `sourceTaskId` | 元 TaskId | ⚪ 素通し | 元データ | text | — | 不可 | バッファ行では無いことがある |
| `sourceBufferId` | 元 BufferId | ⚪ 素通し | 元データ | text | — | 不可 | MilestoneBuffer 由来の行のみ |

## `プロジェクト` と `リソース` について

この 2 つは、**複数プロジェクトの表示とリソースの調整のために中核へ入れた項目**です。
背景は [`../ui/15-multi-project.md`](../ui/15-multi-project.md) にあります。

### `project`

- 選択肢は**プロジェクトの一覧から作られます**。項目定義に選択肢を書き並べません
- **親を持つタスクでは変えられません。** 親に従います
  （親と子が別のプロジェクトにいる形は、どちらの計画なのか決まらないため）

### `assignees`

- **BM3 の Skill 名**（資源の種類）です。画面では「リソース」と呼びます。リソース調整の対象は Skill でよいと決まりました（`Q-039` ✅）
- 1 つのタスクに複数のリソースを割り当てられます
- 画面では読点区切りで表示・入力します（`制御ソフト、画面実装`）
- **リソース別に並べる**とき、そのタスクは**割り当てられたリソースそれぞれの下に現れます**

> ⚠️ **工数や割当率は持っていません**（→ `Q-034`）。
> そのため「誰がいつ何 % 埋まっているか」の負荷のグラフは作っていません。
> 期間だけで描くと事実と違うものになるためです。

## `親タスク` について

**親子関係も「編集できる項目」の一つとして扱っています。**

図の上でドラッグして親を変えることもできますが、
**それだけだと「親から出す方法」が画面のどこにも見当たらない**状態になります。
実際、作った本人が「子の状態から他人にするにはどうすればいい？」と迷いました。

そこで項目として持たせ、一覧の先頭に**「（最上位 — 親なし）」**を置きました。
編集画面を開けば必ず目に入ります。

- 自分自身と**自分の子孫は一覧に出ません**（循環するため）
- 選ぶと、並び順も階層順に自動で整理されます

## 項目を足す・変える・消す手順

### 足す

1. **この文書の表に 1 行足す**
2. モックの `FIELDS`（[`../../mock/index.html`](../../mock/index.html)）に同じ 1 行を足す
3. 中核にした場合のみ、[`20-data-model.md`](20-data-model.md) の読み替え表にも足す
4. `bash scripts/check-spec.sh` を実行して、食い違いがないことを確認する
5. [`../CHANGELOG.md`](../CHANGELOG.md) に記録する

**画面のコードは触りません。** 表の列にも編集画面にも自動で現れます。

### 変える

表示名・区分け・選択肢・補足は、上と同じ手順で変えられます。

⚠️ **`key` を変えるのは「消して足す」と同じ**です。
既存の計画ファイルの値が読めなくなるため、慎重に。

### 消す

⚠️ **素通し項目を画面から消しても、計画ファイルの中身は消えません。**
画面が扱わなくなるだけで、値はそのまま保存され続けます。
これは意図した動きです（ツールが知らない項目を勝手に捨てない）。
