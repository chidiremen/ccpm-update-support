# 画面一覧と操作の索引

> 用語は [`../00-glossary.md`](../00-glossary.md) で定義しています。

## この章の位置づけ

**画面仕様は API 仕様より先に決めます。**

どんな画面があり、そこで何ができるかが決まらないと、必要な API は決められないためです。
たとえば「タスクを 1 件だけ直す画面」があるなら部分更新の API が要りますが、
「XML を丸ごと差し替える画面」しかないなら全文置換だけで足ります。

そのため、**すべての操作に ID を振り**（例 `UI-GANTT-06`）、
API 仕様の側から「この API はどの操作のために存在するか」を参照します。

こうしておくと、後日サーバ側の実物が想定と違っていたときに
**どの画面が影響を受けるかが即座に分かります。** 逆に、どの操作からも参照されない
API は不要だと分かります。

## 画面の一覧

| 画面 | 役割 | 詳細 |
|---|---|---|
| （起動） | **ファイルを開く画面は無い。** ホスト画面からクエリで渡されたプロジェクトを読む | この章の下部 🟢 |
| ガントチャート | 計画を見て、直す。**このツールの主戦場** | [`11-gantt.md`](11-gantt.md) |
| ネットワーク図 | タスクのつながりとボトルネックを見る。**階層は入れ子の枠** | [`12-network.md`](12-network.md) |
| 調整パネル | **1 つのリソースに特化して、試して・決めて・記録する**（ダイアログ） | [`16-adjust.md`](16-adjust.md) |

**複数のプロジェクトを同時に表示できます。**
ガントチャートの並べ方を「リソース別」に変えると、
**同じリソースの作業が全プロジェクト横断で 1 本の時間軸に並びます**
（[`15-multi-project.md`](15-multi-project.md)）。**リソースの調整はここで行います。**

**変更内容は独立した画面にしません。**
ガントチャートとネットワーク図の上に重ねて表示します
（[`13-diff.md`](13-diff.md)）。変更を確かめたい相手は帯や線そのものであり、
別画面に一覧を並べても日程のどこに効くのかが分からないためです。

画面のつながりは [`14-navigation.md`](14-navigation.md) を参照してください。

**タスクが持つ項目の一覧は
[`../interface/24-field-catalog.md`](../interface/24-field-catalog.md) にあります。**
表の列も編集画面も、すべてその定義から作られます。

**実際に触れるモックが [`../../mock/index.html`](../../mock/index.html) にあります。**
ビルド不要です。ブラウザで開けば、表のセル編集・コピー＆ペースト・接続まで試せます。

**ガントチャートとネットワーク図は、同じ計画を別の角度から見たものです。**
どちらでタスクを選んでも、もう片方でも同じタスクが選択された状態になります。

## 起動 — ファイルを開く画面の代わりに 🟢

**2026-09-04 に受領したサーバ側の I/F で、ファイルを開く画面は不要になりました。**

新 GUI は既存のトップ画面（進捗会議マトリクス）から **iframe** で開かれ、
どのプロジェクトを見るかは**起動クエリ**で渡されてきます。

```
既存トップ画面（/）
   │ プロジェクトを選ぶ
   ▼
/external-host?view=gantt&projectIds=17,49      ← ホスト画面。クエリを引き継ぐ
   │ iframe
   ▼
/external/?view=gantt&projectIds=17,49          ← 新 GUI 本体（このリポジトリの成果物）
   │ GET /api/v1/portfolio?projectIds=17,49
   ▼
ガントチャート
```

### `UI-COMMON-10` 起動クエリを受け取る 🟢

| クエリ | 画面側での扱い |
|---|---|
| `view` | 初期表示タブ。`gantt`（既定）/ `network` |
| `projectIds` | **そのまま `GET /portfolio` に渡す。** 表示するプロジェクトの初期値にもなる（`UI-COMMON-08`） |
| `asOf` | そのまま `GET /portfolio` に渡す。応答の `today` が「今日」の線になる |
| `teamId` | 予約。現時点では使わない |

`projectIds` が無いと全件（47 案件）になり重いので、**無い場合は「ホスト画面からプロジェクトを選んでください」と出す**方針にします。
勝手に全件を読みに行きません。

### `UI-COMMON-11` 一部のプロジェクトが読めなかったことを伝える 🟢

応答の `errors[]` が空でなければ、そのプロジェクトのタスクは含まれていません。
**必ず画面上部の帯で伝えます。** 黙って残りだけ表示すると「そのプロジェクトは作業が無い」と誤解されます。
詳細は [`../interface/22-errors.md`](../interface/22-errors.md)。
