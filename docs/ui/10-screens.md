# 画面一覧と操作の索引

> 用語は [`../00-glossary.md`](../00-glossary.md) で定義しています。

## この章の位置づけ

**画面仕様は API 仕様より先に決めます。**

どんな画面があり、そこで何ができるかが決まらないと、必要な API は決められないためです。
たとえば「タスクを 1 件だけ直す画面」があるなら部分更新の API が要りますが、
「XML を丸ごと差し替える画面」しかないなら全文置換だけで足ります。

そのため、**すべての操作に ID を振り**（例 `UI-GANTT-06`）、
API 仕様の側から「この API はどの操作のために存在するか」を参照します。

こうしておくと、後日サーバ側の実物が想定と違っていたときに
**どの画面が影響を受けるかが即座に分かります。** 逆に、どの操作からも参照されない
API は不要だと分かります。

## 画面の一覧

| 画面 | 役割 | 詳細 |
|---|---|---|
| ファイルを開く | 計画ファイルを選び、読み込む | この章の下部 |
| ガントチャート | 計画を見て、直す。**このツールの主戦場** | [`11-gantt.md`](11-gantt.md) |
| ネットワーク図 | タスクのつながりとボトルネックを見る。**階層は入れ子の枠** | [`12-network.md`](12-network.md) |

**複数のプロジェクトを同時に表示できます。**
ガントチャートの並べ方を「担当者別」に変えると、
**同じ人の作業が全プロジェクト横断で 1 本の時間軸に並びます**
（[`15-multi-project.md`](15-multi-project.md)）。**リソースの調整はここで行います。**

**変更内容は独立した画面にしません。**
ガントチャートとネットワーク図の上に重ねて表示します
（[`13-diff.md`](13-diff.md)）。変更を確かめたい相手は帯や線そのものであり、
別画面に一覧を並べても日程のどこに効くのかが分からないためです。

画面のつながりは [`14-navigation.md`](14-navigation.md) を参照してください。

**タスクが持つ項目の一覧は
[`../interface/24-field-catalog.md`](../interface/24-field-catalog.md) にあります。**
表の列も編集画面も、すべてその定義から作られます。

**実際に触れるモックが [`../../mock/index.html`](../../mock/index.html) にあります。**
ビルド不要です。ブラウザで開けば、表のセル編集・コピー＆ペースト・接続まで試せます。

**ガントチャートとネットワーク図は、同じ計画を別の角度から見たものです。**
どちらでタスクを選んでも、もう片方でも同じタスクが選択された状態になります。

## ファイルを開く画面

### 画面の構成

```
┌──────────────────────────────────────────┐
│  計画ファイルを開く                        │
├──────────────────────────────────────────┤
│                                          │
│   ┌──────────────────────────────────┐   │
│   │  ここにファイルをドロップ           │   │
│   │       または                      │   │
│   │    [ ファイルを選ぶ ]              │   │
│   └──────────────────────────────────┘   │
│                                          │
│   最近開いたファイル                       │
│   ・ project-a.xml     2 時間前           │
│   ・ project-b.xml     昨日               │
│                                          │
└──────────────────────────────────────────┘
```

### `UI-OPEN-01` 計画ファイルを指定して開く 🔴推測

**ファイルの指定方法が 2 通り考えられ、どちらになるかはサーバ側次第です**（→ `Q-004`）。

| 方式 | 内容 | 向いている場合 |
|---|---|---|
| **パス指定** | 利用者がファイルの場所を入力し、サーバ側がそこを読む | サーバ側が利用者と同じパソコンで動く（＝今回の構成）。大きなファイルでも速い |
| **アップロード** | 画面側がファイルの中身を読み、サーバ側へ送る | サーバ側が別の場所にあってもよい。ブラウザの制約に素直 |

**今回の構成（同じパソコンの中）ではパス指定が自然**なので、
仕様の初版はパス指定で書いています。ただしブラウザは安全上の理由から
**利用者が選んだファイルの絶対パスを画面側に教えてくれません。**

したがって、パス指定にするなら以下のいずれかが必要です:

- 利用者にパスを文字で入力してもらう
- サーバ側が「開けるファイルの一覧」を返し、そこから選ばせる

⚠️ **この点はサーバ側の作りに強く依存します。最優先の確認事項です**（→ `Q-004`）。

### `UI-OPEN-02` 最近開いたファイルの一覧 🔴推測

一覧をどこに覚えておくかで 2 案あります。

- **画面側に覚える** — ブラウザの保存領域を使う。サーバ側の改修が不要
- **サーバ側に覚える** — 別のブラウザで開いても一覧が残る

サーバ側に該当機能がなければ画面側で持ちます。**初版は画面側**とします。

### `UI-OPEN-03` 開けなかった理由を表示する 🔴推測

失敗の種類ごとに、利用者が次に何をすればよいか分かる文言を出します。
エラーの種類は [`../interface/22-errors.md`](../interface/22-errors.md) を参照。

| 状況 | 利用者に見せる内容 |
|---|---|
| ファイルが見つからない | パスを確認するよう促す |
| XML として壊れている | 壊れている箇所（行・列）を示す |
| 形式が想定と違う | 対応している形式を示す |
| 読み取り権限がない | 権限を確認するよう促す |
