# ガントチャート画面

> 用語は [`../00-glossary.md`](../00-glossary.md) で定義しています。
> 操作 ID の索引は [`10-screens.md`](10-screens.md) にあります。
> 実際に触れるモックが [`../../mock/index.html`](../../mock/index.html) にあります。

## この画面の役割

**計画を見て、直す**画面。このツールの主戦場です。

左が **Excel 風の表**、右が時間軸の帯。編集はほぼすべてここで完結します。

## 基本方針 — 会社で慣れている道具に寄せる

**利用者はすでに Excel で計画を扱っています。** 新しい操作を覚えてもらうより、
**知っている操作がそのまま効く**ほうが早い。学習コストがゼロだからです。

そのため、表の操作は Excel に寄せます。独自の操作を発明しません。

### ただし Excel の操作「だけ」にはしない

**キーボードでできることは、マウスでもできるようにします。**

| やりたいこと | キーボード | マウス |
|---|---|---|
| 階層を下げる・上げる | <kbd>Alt</kbd>+<kbd>←</kbd> / <kbd>→</kbd> | 行を掴んで横にずらす |
| 行を並べ替える | 切り取り → 貼り付け | 行を掴んで縦に動かす |
| 行全体を選ぶ | <kbd>Shift</kbd>+<kbd>Space</kbd> | 行番号をクリック |
| 依存関係をつなぐ | 先行タスクのセルで <kbd>Enter</kbd> | ハンドルから一覧／ドラッグ |

**どちらか一方に寄せません。** 人によって手が違い、場面によっても違うためです。
細かい値を確実に入れたいときはキーボードが速く、
「この作業をここへ持っていく」はマウスのほうが速い。

## 画面の構成

```
┌──────────────────────────────────────┬───────────────────────────────┐
│ [日][週][月] [表示する列▾] [行を挿入][削除][→|下げる][|←上げる]        │
├──────────────────────────────────────┼───────────────────────────────┤
│ タスク名        種別  期間 着手日 …   │  4月      5月      6月         │
├──────────────────────────────────────┼───────────────────────────────┤  ← 常時固定
│ （マイルストン帯）                     │      ◆設計完了      ◆納品      │
├──────────────────────────────────────┼───────────────────────────────┤
│ ▼ 設計フェーズ   タスク  20d          │  ▭▭▭▭▭▭▭▭                     │
│   ● 要件定義     タスク   8d 04-01    │  ▓▓▓▓                         │
│   ● 基本設計     タスク  12d 04-13    │      ▓▓▓▓▓▓                   │
│   ● MSバッファ   バッファ 3d 04-29    │            ▒▒                 │
│   ● ◆ 設計完了   マイルストン 0d      │              ◆                │
│ ▼ 実装フェーズ   タスク  35d          │              ▭▭▭▭▭▭▭          │
└──────────────────────────────────────┴───────────────────────────────┘
   ● = クリティカルチェーン上   ▓ 通常   ▒ バッファ   ◆ マイルストン
```

**タスク名の列は固定**します。項目が数十あり横に長いため、
スクロールしたときにどの行を見ているか分からなくなるのを防ぎます
（Excel のウィンドウ枠の固定と同じ考え方）。

## Excel 風の操作 🔴推測

### `UI-GANTT-10` セルを選ぶ・移動する

- クリックでセルを選ぶ。<kbd>Shift</kbd>+クリックで範囲選択
- 矢印キーで移動。<kbd>Shift</kbd>+矢印で範囲を広げる
- <kbd>Tab</kbd> / <kbd>Shift</kbd>+<kbd>Tab</kbd> で左右
- 行番号をクリックすると、その行全体を選ぶ

### `UI-GANTT-11` セルを編集する

- **文字を打ち始めるとそのまま編集に入る**（Excel と同じ）
- <kbd>F2</kbd> またはダブルクリックでも編集開始
- <kbd>Enter</kbd> で確定して下へ、<kbd>Tab</kbd> で確定して右へ
- <kbd>Escape</kbd> で取り消し
- <kbd>Delete</kbd> で選択範囲を空にする

> ### ⚠️ 日本語入力（IME）に関する実装上の注意
>
> 「打ち始めたら編集に入る」を**キー入力の検知で作ってはいけません。**
>
> **日本語入力はキー入力の事象を発生させません。** IME を通した文字は
> 変換の事象として届くため、キー入力を見て入力欄を作る方式だと、
> **半角英数字では動くのに日本語では編集が始まらない**という状態になります。
>
> 日本語の計画ファイルを扱う道具でこれは致命的です。
>
> **対策**: 入力欄を**常にカーソル位置のセルに重ねて置いておく**（普段は透明で、
> 下のセルをクリックできる状態にする）。文字が入ってきたら表示に切り替える。
> こうすれば、半角でも日本語でも同じように編集が始まります。
>
> この点はモックで実際に踏んで確認しました。

### 選択肢のある項目 🔴推測 (`Q-027`)

工程区分のように**決まった選択肢から選ぶ項目**は、文字入力ではなく一覧から選ばせます。
自由入力にすると表記ゆれと打ち間違いが入るためです。

⚠️ どの項目が選択肢を持つかはサーバ側から受け取りたい（→ `Q-027`）。
素通し項目のままだと、この判断ができません。

### `UI-GANTT-12` コピー・切り取り・貼り付け

<kbd>Ctrl</kbd>+<kbd>C</kbd> / <kbd>X</kbd> / <kbd>V</kbd>。
**タブ区切りでやり取りするため、Excel との間で相互に貼り付けできます。**
これは「会社で慣れている道具に寄せる」上で外せない点です。

⚠️ **決めるべきこと**（→ `Q-029`）:

| 何をコピーしたか | 貼り付けたときどうなるべきか |
|---|---|
| セル（値だけ） | その値が入る。素直 |
| 行（タスクごと） | **タスクの複製になる。** 識別子は新規採番？ 名前は変える？ |
| 複数行 | **その行同士の依存関係は保つ？ 外へ出ている依存は？** |

現在の想定は「セル単位の値のコピー」のみ。行の複製は未定です。

### `UI-GANTT-13` 行の挿入・削除

- 挿入は選択行の下。**挿入したらカーソルを新しい行へ移す**
  （移さないと、続けて削除を押したときに元の行が消えて事故になります）
- 削除は選択範囲の行。**子タスクも一緒に消えます**

### `UI-GANTT-14` 元に戻す・やり直し

<kbd>Ctrl</kbd>+<kbd>Z</kbd> / <kbd>Ctrl</kbd>+<kbd>Y</kbd>。

**Excel 風を名乗る以上、これは必須です。** 「10 個直して 3 個前に戻したい」は必ず起きます。

保存前の変更は[変更内容の確認画面](13-diff.md)で止められるためファイルは壊れませんが、
それは事故を防ぐ仕組みであって、操作を取り消す仕組みではありません。**別のものです。**

### `UI-GANTT-19` 表とチャートの分割比率を変える 🔴推測

境目をドラッグして、左右の広さを変えられるようにします。
表の項目を多く見たいときと、日程を広く見たいときで、欲しい比率が違うためです。

**必ず指でも動くようにします。** マウスの押下だけを見ていると、
タッチ環境では**まったく動きません**（実際にこの作り込みで一度やらかしました）。

- ポインタの入力として扱う（マウスと指を 1 つの実装で受ける）
- 境目の**当たり判定を広げる**。見た目は細くてよいが、指では細い的は押せない
- ブラウザのスクロールに取られないよう、境目ではスクロールを無効にする
- **既定の比率のボタンも置く**（表を広く / 半々 / 図を広く）。
  狭い画面では、境目を引くより確実

### `UI-GANTT-20` 表示する時間の単位を変える 🔴推測

日 / 週 / 月 を切り替えます。

**拡大率だけでなく、目盛りの粒度も変えます。**
拡大しても目盛りが週のままでは、単位を切り替えた意味がありません。

| 単位 | 目盛り | 使う場面 |
|---|---|---|
| 日 | 1 日ごと。土日は薄く | 直近の数週間を細かく詰める |
| 週 | 週の頭ごと | 通常の作業 |
| 月 | 月ごと | 計画全体を俯瞰する |

**選択中の単位はボタンに表示します。** どの単位で見ているか分からないと、
帯の長さの読み違いにつながります。

## 行をマウスで扱う 🔴推測

### `UI-GANTT-24` 行全体を選ぶ

- **行番号をクリック**すると、その行の全項目が選ばれる
- <kbd>Shift</kbd>+<kbd>Space</kbd> でも同じ（Excel と同じ操作）
- <kbd>Shift</kbd>+クリックで範囲を広げる

**行番号の列は「つまみ」として見せます。**
マウスを乗せたときと選択中に目印を出し、カーソルの形も変えます。
掴めることが見て分からなければ、**ドラッグできることに気づかれません。**

### `UI-GANTT-26` 行番号のダブルクリックで全項目を編集

**行番号をダブルクリックすると、プロパティ編集画面が開きます。**
数十ある項目のうち、表に出していないものもここで編集できます。

**セルのダブルクリックは、いままで通りその場編集です。** すみ分けています。

- 行番号 → **全項目**（じっくり直したいとき）
- セル → **その 1 項目**（Excel のように素早く直したいとき）

編集画面の中身は
[`../interface/24-field-catalog.md`](../interface/24-field-catalog.md) の
項目定義から作られます（`UI-COMMON-05`）。

> **実装上の注意**: `pointerdown` で既定動作を止めると、
> ブラウザは `dblclick` を発生させません。
> ダブルクリックは自前で判定する必要があります。
> （この作り込みで実際に踏みました）

### `UI-GANTT-25` 行を掴んで並べ替える・階層を変える

**縦の位置で「どこに入るか」、横の位置で「どの階層に入るか」**を決めます。
1 回のドラッグで並べ替えと親子変更の両方ができます。

```
ドラッグ中の表示:

  ▸ 設計フェーズ
      要件定義
  ━━━━━━━━━━━━━━━      ← 挿入位置を示す線
      ┊    基本設計       ← 横にずらすと、この深さに入る
    実装フェーズ
```

**決めごと**:

- **子孫は一緒についていく。** 親だけ動いて子が置き去りになると計画が壊れます
- **階層は「1 つ上の行より 1 段深いところまで」。**
  それ以上深くすると、親のいない子ができてしまいます
- 複数行を選んでいれば、まとめて動かせます
- 折りたたまれた親の中に入れたときは、**その親を開きます**
  （入れたはずの行が見えないと、消えたと勘違いされるため）
- **位置も階層も変わらなかった場合は、履歴に積みません。**
  積むと「元に戻す」が空振りします
- 指でも掴めるようにします（ポインタの入力として扱う）

## 階層構造 🔴推測 (`Q-008`)

タスクをまとめるとき、ガントチャートでは階層で表します。

### `UI-GANTT-01` 階層表示と折りたたみ

- 親タスクは折りたたみ・展開できる
- 親の帯は、子をすべて含む範囲として描く

### `UI-GANTT-15` 階層を上げ下げする

- <kbd>Alt</kbd>+<kbd>→</kbd> で下げる（直前の同じ階層の行を親にする）
- <kbd>Alt</kbd>+<kbd>←</kbd> で上げる（親の階層へ出し、親の直後へ移す）

> **なぜ <kbd>Tab</kbd> ではないのか** — Excel では <kbd>Tab</kbd> はセル移動です。
> ここで階層操作に割り当てると、慣れた操作を壊すことになります。

### `UI-GANTT-16` 親行は編集させない

親の**期間・着手日・完了日・進捗は子から決まります。**
そのため灰色にして入力を受け付けません（Excel の数式セルと同じ扱い）。

手で入れられると、子と食い違ったときにどちらが正しいか分からなくなります。

## 接続（先行 / 後続）🔴推測

**CCPM では、この接続が計画の本体です。** 繋ぎやすさに最も気を配ります。

接続の UI は[ネットワーク図](12-network.md)と**同じ部品**を使います。
画面が変わるたびに操作を覚え直すのは無駄だからです。

### `UI-CONNECT-01` 先行タスクのセルから繋ぐ

**先行タスクの列のセルは、文字入力ではなく接続の一覧を開きます。**

タスク名を打たせると表記ゆれや打ち間違いが入るためです。
一覧は検索で絞り込めます。既存の接続はその場で外せます。

### `UI-CONNECT-02` 帯のハンドルから繋ぐ

行を選ぶと、ガントの帯の**左右に接続ハンドル**が出ます。

- **左（in）** = 先行タスク。この前に終わるもの
- **右（out）** = 後続タスク。この後に始まるもの

### `UI-CONNECT-03` クリックでもドラッグでも繋げる

**両方できるようにします。人によって好みが分かれるためです。**

- ハンドルを**クリック** → 検索付きの一覧から選ぶ。**相手が遠い・多いときに有効**
- ハンドルから**ドラッグ** → 相手の帯やノードにドロップ。**相手が近くに見えているときに速い**

### `UI-CONNECT-04` 堂々巡りを止める

循環する接続（A→B→C→A）は**作らせません。**
繋ごうとした時点で断り、理由を示します。

後で検証で弾くより、その場で止めるほうが親切です。

### `UI-GANTT-08` 依存関係を線で表示する 🔴推測 (`Q-009`)

既定では**選択中の行に関わる依存だけ**を描きます。全部描くと線だらけで読めません。
全部表示に切り替える手段は用意します。

## マイルストン 🔴推測 (`Q-028`)

### `UI-GANTT-17` マイルストン帯を常に表示する

**時間軸の直下に固定の帯を置き、スクロールしても消えないようにします。**

マイルストンは計画全体の基準になる時点です。
行をスクロールして視界から消えると、
「いま見ているタスクが納期に対してどの位置か」が分からなくなります。

帯には次を表示します:

- マイルストンを ◆ と名前で
- **マイルストンバッファ**をその手前のハッチングで
- マイルストンの日付に縦線を落とし、下の帯と対比できるようにする

⚠️ マイルストンとマイルストンバッファが計画ファイル上でどう表現されるかは
未確認です（→ `Q-028`）。

## 日程の再計算は誰がやるか 🔴推測 (`Q-026`)

**期間を変えたとき、後続タスクの日付は画面側で計算しません。**

| 誰が | 何を |
|---|---|
| **画面側** | いま編集した帯の長さだけを即座に反映する。**これは計算ではなく入力の反映** |
| **サーバ側** | 後続タスクのずれ、資源競合の解消、バッファの再配置 |

### なぜサーバ側に寄せるのか

CCPM の日程計算は、依存関係の前進計算だけでなく**資源の競合**まで考慮します。
これを画面側でも実装すると**二重持ちになり、必ずズレます。**

ズレた絵を見て調整を判断されるほうが、少し待つより危険です。

### これによる方針の変更

以前は「編集中はサーバ側と通信しない、保存時にまとめて送る」としていました。
**これを部分的に撤回します。**

打鍵のたびに送るのではなく、**入力が落ち着いたら**計算を依頼します。
サーバ側に「計算だけして保存しない」呼び出しが必要です（→ `Q-026`）。

## 表示する列 🔴推測 (`Q-030`)

タスクに紐づく項目は**数十あります。** 全部を常に出すことはできません。

### `UI-GANTT-18` 列の出し入れ

表示する項目をドロップダウンで選びます。一覧は 2 つに分けて示します。

- **中核項目** — ツールが意味を理解するもの
- **素通し項目** — 意味を解釈せず、そのまま保存するもの

この区別の意味は [`../interface/20-data-model.md`](../interface/20-data-model.md) を参照。

⚠️ 選択肢から選ぶ項目（工程区分など）があるかは未確認です（→ `Q-027`）。
あるならドロップダウンにできますが、素通し扱いのままだと入力の助けが出せません。

## 複数のプロジェクトを一度に見る 🔴推測

**詳しくは [`15-multi-project.md`](15-multi-project.md) にまとめてあります。**
ここでは、この画面から見たときの要点だけを書きます。

### `UI-GANTT-27` 並べ方を切り替える

| 並べ方 | 行が何になるか | 何に使うか |
|---|---|---|
| **プロジェクト別**（既定） | プロジェクトが親。その下はこの章の階層のまま | 計画を作る・直す |
| **担当者別** | 人が親。その下にその人の全プロジェクトの作業を日程順 | **リソースの調整** |

**担当者別では、次の操作が効きません。**
人の下の並びには意味がなく（日程順に並べているだけ）、
そこに行を挿したり階層を作ったりできると、何が起きたのか説明できなくなるためです。

- `UI-GANTT-13` 行の挿入・削除
- `UI-GANTT-15` 階層の上げ下げ
- `UI-GANTT-25` 行を掴んでの並べ替え
- `UI-GANTT-08` 依存関係の線（同じタスクが複数の行に出るため、引く先が定まらない）

**`UI-GANTT-11` のセル編集はできます。** 出ているのは同じタスクの実体そのものです。

ボタンは押せない見た目にします。**押せるのにできないのは嘘になる**ためです。

### `UI-GANTT-28` 担当者別では、行を掴んで落とす＝担当の付け替え

`UI-GANTT-25` の「掴んで落とす」を、担当者別では**担当の付け替え**に使います。
別の人の欄へ落とすと、その人に担当が移ります。何が起きるかは札に言葉で出します。
詳細と札の文言は [`15-multi-project.md`](15-multi-project.md)。

### `UI-COMMON-08` プロジェクトの色

プロジェクトの色は**行の左端の帯**に置きます。

帯の塗りと枠線は、すでに `UI-GANTT-03`（クリティカルチェーン）と
`UI-GANTT-04`（バッファ）が使っています。
そこへ重ねると**同じ場所が 2 つの意味を持ち**、読み取れなくなります。

### 判定はしません

**資源の取り合いを自動で判定して警告を出すことはしません。**
負荷のグラフも作りません（工数が未確認のため → `Q-034`）。
理由は [`15-multi-project.md`](15-multi-project.md) にあります。

## この画面が必要とする API

| 操作 | 必要なもの |
|---|---|
| 表示 | `GET /api/v1/plans/{planId}` |
| セル編集・行操作・接続 | なし（画面側で保持し、保存時にまとめて送る）🔴 (`Q-006`) |
| **日程の再計算** | **未定の新しい呼び出し**（→ `Q-026`） |
| 保存 | [`13-diff.md`](13-diff.md) を参照 |

⚠️ サーバ側に**タスク単位の部分更新**があるなら、変更の送り方を変える余地があります
（→ `Q-006`）。現在は XML 全文置換のみを前提にしています。
