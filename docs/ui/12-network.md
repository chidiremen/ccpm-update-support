# ネットワーク図画面

> 用語は [`../00-glossary.md`](../00-glossary.md) で定義しています。
> 操作 ID の索引は [`10-screens.md`](10-screens.md) にあります。

## この画面の役割

**タスクがどうつながっているか**を見る画面。
ガントチャートが「いつ」を見るのに対し、こちらは「順序と依存」を見ます。

どこがボトルネックか、どの流れが合流するか、
遅れがどこまで波及するかは、この図でこそ分かります。

## 図法について 🔴推測 (`Q-021`)

「ネットワーク図」と呼ばれる図法は複数あり、**どれを指すかが未確定です。**

| 図法 | ノード | 矢印 | 備考 |
|---|---|---|---|
| **プレシデンス・ダイアグラム** | タスク | 依存関係 | 現代の主流。多くのツールがこれ |
| アローダイアグラム（PERT） | 時点 | タスク | 古典的。ダミー作業が必要で複雑 |

**初版はプレシデンス・ダイアグラム（ノード＝タスク）を想定して書いています。**
タスクが箱になるため、ガントチャートのタスク一覧と 1 対 1 で対応し、
画面間で選択状態を引き継ぐのも自然だからです。

⚠️ 既存のツールや社内の慣習でアローダイアグラムが期待されている場合、
**この章はほぼ全面的に書き直しになります。** 早めに確認してください（→ `Q-021`）。

## 操作の仕様

### `UI-NET-01` タスクをノード、依存関係を矢印で表示する 🔴推測 (`Q-021`)

**ノードに表示する内容**（🔴推測）:

- タスク名（長い場合は省略し、マウスを乗せると全体を表示）
- 期間
- 担当

ノードの大きさは**一定**にします。期間に比例させると長いタスクが図を占有し、
つながりが見えにくくなるためです（期間はガントチャートで見ます）。

**矢印**は依存の向き（前工程 → 後工程）を示します。

### `UI-NET-02` クリティカルチェーンを強調表示する 🔴推測 (`Q-011`)

クリティカルチェーン上のノードと矢印を、太さと色で強調します。

**色だけで区別しません。** 色の見え方には個人差があるため、
太さ・枠線の形といった色以外の手がかりも併用します。

⚠️ 計算を誰がするかはガントチャートと同じ論点です（→ `Q-011`）。

### `UI-NET-03` ノードを選び、詳細を表示する 🔴推測

ノードをクリックすると詳細パネルを表示します。
同時に、**そのタスクにつながる依存を強調**し、関係のないものを薄くします。
影響範囲がひと目で分かります。

選択状態はガントチャートと共有します（`UI-COMMON-04`）。

## 接続（先行 / 後続）— ガントと同じ部品を使う 🔴推測

**CCPM では接続そのものが計画の本体**です。この図はそれを直接いじる場所になります。

**操作はガントチャートと同一**にします（`UI-CONNECT-01`〜`04`、
[`11-gantt.md`](11-gantt.md) に定義）。画面が変わるたびに操作を覚え直すのは無駄だからです。

### `UI-NET-07` ノードのハンドルから繋ぐ

ノードを選ぶと、**左右に接続ハンドル**が出ます。

- **左（in）** = 先行タスク。この前に終わるもの
- **右（out）** = 後続タスク。この後に始まるもの

**クリックすれば検索付きの一覧**が開き、**ドラッグすれば相手のノードに直結**できます。
どちらでも繋げます（`UI-CONNECT-03`）。

ガントの帯に出るハンドルと、見た目も操作も揃えます。

### この図ならではの利点

ガントでは帯が時間軸上に散らばるため、離れたタスク同士を繋ぐのに
スクロールが必要になります。**この図では前後関係が横に並ぶため、
繋ぎたい相手が近くに見えていることが多く、ドラッグが効きます。**

逆に、日付を見ながら繋ぎたいときはガントのほうが向きます。
**どちらでも同じことができる**のは、そのためです。

### `UI-NET-04` 拡大・縮小・移動する 🔴推測

- マウスホイールで拡大・縮小
- ドラッグで移動
- 「全体表示」ボタンで計画全体を画面に収める

拡大率が小さいときは、ノード内の文字を省略します（読めない文字を描いても無駄なため）。

### `UI-NET-05` ノードを自動配置する 🔴推測 (`Q-020`)

**配置は画面側が自動計算します。** 依存関係の向きに沿って左から右へ、
同時に進められるタスクを縦に並べる方式（階層レイアウト）を想定します。

**未確定の点**: 利用者が手で動かした配置を**覚えておく必要があるか**。

| 案 | 内容 |
|---|---|
| **覚えない**（初版） | 開くたびに自動配置。実装が単純 |
| 画面側で覚える | ブラウザの保存領域に置く。別のパソコンでは引き継がれない |
| 計画ファイルに保存する | どこでも同じ配置。**ただし計画ファイルに座標を書き込むことになる** |

⚠️ 3 案目は、**計画ファイルに本来の計画情報でないものを混ぜる**ことになります。
他のツールがそのファイルを読めなくなる恐れがあるため、慎重な判断が必要です（→ `Q-020`）。

**初版は「覚えない」**とします。

### `UI-NET-08` マイルストンとバッファもノードにする 🔴推測 (`Q-028`)

マイルストンとバッファも**タスクと同じくノードとして描きます。**
種別ごとに見た目を変えます（マイルストンは枠を太く、バッファは破線）。

これらを図から省くと、**バッファがどの流れを守っているかが見えなくなります。**
CCPM ではそこが要点なので、省きません。

表示の切り替えはできるようにします（タスクの流れだけを追いたいときのため）。

### `UI-NET-06` 大きな計画でも扱えるようにする 🔴推測 (`Q-012`)

⚠️ **想定するタスク数が未確認です**（→ `Q-012`）。これは実装方式を左右します。

| タスク数 | 実現方法 |
|---|---|
| 〜200 | 素直に全部描いてよい |
| 200〜1000 | 描画方法の工夫が要る（表示範囲外を描かない等） |
| 1000〜 | 図の作りを見直す必要がある（折りたたみ前提、間引き表示） |

**規模が分からないうちは、まず素直に全部描く実装にします。**
先回りして複雑にすると、無駄になったときの損失が大きいためです。

規模が大きい場合に備え、次の逃げ道を用意しておきます:

- 親タスク単位で折りたたむ
- 選択したタスクの前後 N 段階だけを表示する

## 差分の重ね表示 🔴推測 (`Q-031`)

ガントチャートと同じ切り替え（オフ / 濃淡 / 見比べ）を置きます。
定義は [`13-diff.md`](13-diff.md) にあります。

- **濃淡** — 変更のないノードと線を薄くする
- **見比べ** — 図を左右に並べ、左＝読み込み時点 / 右＝いま

**接続の変更を確かめるには、この図がいちばん向いています。**
ガントでは線が帯の間を這うため、増えた線・消えた線が読み取りにくいためです。

## この画面が必要とする API

ガントチャートと**同じ計画データを使います**。追加の API は必要ありません。

| 操作 | 必要な API |
|---|---|
| 計画を表示する | `GET /api/v1/plans/{planId}`（ガントと共通） |
| 配置の計算 | なし（画面側で計算） |

| 接続の追加・削除 | なし（画面側で保持し、保存時にまとめて送る） |

⚠️ `Q-011`（クリティカルチェーンの計算）と `Q-020`（配置の保存）の回答次第で、
API が増える可能性があります。また接続を変えると日程が動くため、
`Q-026`（日程の再計算）の対象にもなります。
